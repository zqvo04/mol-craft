# Mol-Craft 직접 조립·스케치 UX 개선 설계

## 1. 현재 상태 감사

### 보존할 강점

현재 조립 도구는 원자 배치 전에 VSEPR 슬롯과 결합 가능 여부를 고스트로 보여 주고, 실제 클릭 때 같은 좌표를 사용한다. 따라서 “보여 준 자리와 실제 결과가 다르지 않다”는 중요한 직접 조작 원칙을 이미 지킨다. 2D와 3D는 같은 분자 상태를 공유하며, 보기 전환이 분자를 암묵적으로 바꾸지 않는다. 선택 순서 표시, 결합 대기 강조, 원자가 오류의 즉시 안내, 명시적 수소 채우기와 실행취소도 교육용 조립 환경의 신뢰 기반이다.

### 관찰한 마찰 지점

1. 데스크톱 상단에 보기·선택·지우개·결합·전하·원소 팔레트·구조 단위·되돌리기·복제·수소 채우기·2D/3D 전환이 여러 줄로 동시에 노출된다. 현재 활성 도구와 다음 행동보다 전체 기능 목록이 먼저 보이므로 초심자가 조립의 첫 단계를 판단하기 어렵다.
2. 붙이기, 기존 원자 결합, 결합차수 변경, 고리 삽입이 서로 다른 모드에 분산되어 있다. 결합 도구는 원자 두 번 클릭과 결합선 클릭이라는 두 동작을 함께 담고 있어, 사용자가 무엇을 클릭해야 하는지 매번 기억해야 한다.
3. 3D 조립은 앵커 위 호버와 작은 히트 범위에 의존한다. 고스트 자체는 좋지만, 조밀한 분자·터치 화면·초심자의 느린 포인팅에서는 목적 원자를 안정적으로 고르기 어렵다.
4. 우클릭 삭제, R/휠 슬롯 순환, 숫자키 원소 선택은 빠른 사용자에게 유용하지만, 화면의 핵심 조작으로 충분히 드러나지 않는다. 모바일에는 우클릭과 호버라는 전제가 성립하지 않는다.
5. 2D 모드는 스켈레탈 표기를 잘 보여 주지만, 사용자는 “2D 보기”가 독립적인 드로잉 워크벤치인지 3D 조립의 투영인지 즉시 알기 어렵다. 2D에서 비어 있는 공간을 클릭하여 자유롭게 사슬을 시작하거나, 드래그로 결합을 그리는 직접 스케치 제스처도 없다.
6. 삭제는 지우개/우클릭에서 가지치기, Delete에서는 정확 선택 삭제로 다르게 동작한다. 유용한 차이지만 사전 예고와 되돌리기 직후의 명확한 결과 요약이 부족하면 예측 불가능하게 느껴질 수 있다.
7. 단일 실행취소는 제공되지만 재실행, 최근 조작 타임라인, 대규모 삭제·고리 삽입 전의 의미 있는 확인 표면은 없다.

### 설계 결론

직접 조립 경험은 기능을 더 얹기보다 **조립 흐름을 한 개의 자연스러운 제스처 언어로 통합하고, 필요한 순간에만 다음 행동을 제안하는 것**이 우선이다. 고정된 상단 도구 모음은 편집기의 제어판이 아니라, 현재 과업에 맞춰 바뀌는 작고 명확한 조립 콘솔로 재구성해야 한다.

## 2. 목표 경험과 상호작용 원칙

### 2.1 목표 문장

> 학생은 원하는 원소 또는 구조 단위를 고르고, 분자의 **보이는 유효 자리**를 가리킨 뒤, 초록색 미리보기 확인 후 한 번 눌러 조립한다. 잘못 조립했으면 결과를 이해한 채 즉시 되돌린다.

이 목표에서는 도구의 이름을 외우는 것보다 다음 상태가 항상 명확해야 한다.

| 조작 상태 | 화면이 반드시 답해야 할 질문 | 시각·동작 피드백 |
|---|---|---|
| 대기 | “무엇을 할 수 있나?” | 마지막으로 쓴 원소, 새 구조 시작, 카탈로그·구조 단위 진입점 |
| 재료 선택 | “지금 무엇을 붙이나?” | 선택한 원소/구조 단위 이름·색·단축키를 큰 칩으로 고정 표시 |
| 대상 조준 | “여기에 가능한가?” | 유효 결합은 초록, 원자가 포화는 회색, 비공유쌍 자리는 보라·잠금 표기 |
| 커밋 직전 | “정확히 무엇이 바뀌나?” | 새 원자/결합/고리 전체를 반투명으로 표시하고 변화 요약 |
| 커밋 직후 | “무엇이 일어났나?” | 짧은 성공 모션, 새 구조 강조, `되돌리기`와 결과 문장 |
| 오류 | “왜 안 되고 다음에는 뭘 하나?” | 원인이 있는 자리만 강조하고 해결 행동을 하나 제안 |

### 2.2 모드 수를 줄이는 대신 대상별 동작을 명확히 한다

현재 `place`, `bond`, `erase`, `select`, `ring`을 그대로 노출하지 않는다. 사용자 표면에는 **탐색**, **조립**, **선택**의 세 가지 작업 상태만 남긴다. 내부 구현의 도구 상태는 유지할 수 있지만, 사용자가 이해해야 하는 문법은 줄인다.

| 작업 상태 | 기본 제스처 | 원자 위 | 결합 위 | 빈 캔버스 | 보조 제어 |
|---|---|---|---|---|---|
| 탐색 | 드래그/핀치 | 정보만 표시 | 정보만 표시 | 카메라 이동 | 2D/3D 보기 |
| 조립 | 탭/클릭 | 선택 재료를 유효 슬롯에 붙임 | 결합 속성 메뉴 표시 | 2D에서는 새 골격 시작, 3D에서는 `새 조각 시작` 제안 | 원소·구조 단위·전하·결합 속성 |
| 선택 | 탭/클릭/드래그 | 선택/다중 선택 | 결합 선택 | 박스·올가미 선택 | 선택 컨텍스트 바 |

삭제는 별도 모드가 아니라 선택 컨텍스트 바의 **삭제**와 데스크톱 보조 제스처로 제공한다. 즉, 평소 조립 중에 실수로 지우개로 남는 위험을 없앤다. 빠른 사용자는 Backspace/Delete와 우클릭을 계속 사용할 수 있지만, 제품의 주 경로는 선택 후 삭제다.

### 2.3 상황형 조립 콘솔

상단의 다층 도구 막대를 다음 세 영역으로 재편한다.

1. **전역 헤더:** 분자 이름·저장 상태·되돌리기/재실행·공유·분석만 둔다.
2. **조립 콘솔:** 캔버스 바로 아래 또는 모바일 하단에 배치한다. 선택 재료 칩, 최근 원소 4개(C/N/O/H 기본), `더 보기`, `구조 단위`, 2D/3D 보기 전환을 둔다.
3. **선택 컨텍스트 바:** 원자·결합·여러 원소가 선택될 때만 나타난다. 전하, 결합차수, 복제, 삭제, 측정, 정렬/최적화처럼 지금 선택에 유효한 행동만 보여 준다.

이 구조에서는 `결합·차수`가 항상 보일 필요가 없다. 두 원자를 선택하면 “결합 만들기”가, 결합 하나를 선택하면 “단일/이중/삼중/방향족”이 나타난다. 사용자는 도구가 아니라 **대상과 의도**를 중심으로 동작한다.

## 3. 직접 조립 흐름 상세 설계

### 3.1 원자 추가

#### 2D 스케치

2D는 학생이 가장 빠르게 구조를 생각으로 바꾸는 **기본 조립 면**으로 정의한다. 빈 캔버스를 한 번 클릭하면 선택된 원소로 새 조각을 시작하고, 기존 원자에서 드래그하면 다음 원자를 붙이는 방향을 직접 정한다. 기존 원자를 단순 클릭했을 때는 현재처럼 유효한 결합 방향을 고스트로 보여 주되, 드래그가 있었으면 드래그 방향을 우선한다. 시스템은 결합 길이와 120°/109.5° 성격의 레이아웃을 보정하되, 사용자가 의도한 골격 방향을 무시하지 않는다.

| 2D 입력 | 제안 동작 | 안전장치 |
|---|---|---|
| 빈 곳 탭 | 새 원자/새 조각 시작 | 새 조각 여부와 현재 분자에 대한 영향 표시 |
| 원자 탭 | 기본 유효 방향에 원자 추가 | 유효 슬롯 고스트와 원자가 상태 표시 |
| 원자에서 드래그 후 놓기 | 드래그 방향에 원자·단일결합 추가 | 방향 스냅, 길이 보정, 실패 시 커밋하지 않음 |
| 선택 원자에서 드래그해 다른 원자에 놓기 | 기존 원자끼리 결합 시도 | 고리 닫기 여부·원자가·거리 미리 검증 |
| 결합 탭 | 결합 속성 작은 메뉴 | 단일/이중/삼중/방향족 중 유효한 선택만 활성화 |

#### 3D 조립

3D는 기하와 배좌를 이해하는 **조립 결과·공간 실험 면**으로 정의한다. 기본 동작은 앵커 원자 호버/길게 누르기 → 유효 슬롯 고스트 → 탭 커밋이다. 복잡한 분자에서는 손가락이나 커서가 가리는 문제를 피하기 위해, 대상 원자를 누른 뒤 0.25초 후 원자 주변에 슬롯 링을 띄우고 원하는 슬롯을 직접 탭할 수 있어야 한다. 현재의 R/휠 슬롯 순환은 이 링이 없을 때의 고급 단축키로만 남긴다.

고정 카메라에서 원자가 겹칠 경우에는 작은 **원자 탐색기**를 제공한다. 커서 근처의 후보 원자 이름과 인덱스를 세로로 보여 주고, 방향키/휠로 후보를 바꾸면 고스트가 즉시 바뀐다. 이는 히트테스트 반경을 무작정 키워 엉뚱한 원자를 잡는 문제를 줄인다.

### 3.2 결합과 결합차수

결합 생성은 “결합 도구를 켠 뒤 두 번 클릭”이 아니라 **두 원자 선택 → 결합 만들기**가 주 경로다. 단일 원자가 선택되면 조립 콘솔은 새 원자 추가를 우선하고, 두 원자가 선택되면 연결 가능 여부와 예상 결과를 즉시 표시한다. 학생이 두 원자를 선택한 이유가 측정일 수도 있으므로, 선택 컨텍스트 바에서 `거리 측정`과 `결합 만들기`를 나란히 제시하되 결합 가능하면 전자를 기본 강조한다.

결합 하나를 탭했을 때는 화면 중앙에 대형 모달을 띄우지 않고, 결합 위에 붙는 작은 속성 팝오버를 사용한다. 현재 차수, 가능한 다음 차수, 방향족화 가능 여부, 해당 차수가 바꿀 원자가 상태를 한 줄로 표시한다. 이중·삼중결합을 선택하는 순간 주변의 암시적 수소와 혼성화 변화도 부드럽게 미리 보여 준다.

### 3.3 구조 단위와 고리 삽입

구조 단위는 “특수한 다른 도구”가 아니라 조립 콘솔의 `구조 단위` 서랍에서 여는 재료다. 서랍은 최근 사용·고리·헤테로고리·기능기·생체 단위로 나누고, 각 카드에는 첨부 원자, 결과 결합, 필요한 빈 원자가, 교육 태그를 함께 표시한다.

고리 삽입의 주 흐름은 **단위 선택 → 앵커 조준 → 전체 반투명 미리보기 → 회전 핸들 또는 좌우 버튼 → 커밋**이다. R 키 30° 회전은 유지하되, 회전 결과가 붙을 원자와 가장 가까운 원자만 하이라이트해 방향을 인지하게 한다. 고리 삽입 뒤의 자동 완화는 “배치가 정리되었습니다”로만 끝내지 않고, 전후 기하 차이와 되돌리기 버튼을 보여 준다.

### 3.4 전하와 수소

전하는 상단의 독립 버튼 묶음보다 원자 선택 컨텍스트 바에서 다뤄야 한다. 원자 하나가 선택되면 `−`, `0`, `+`와 현재 형식전하가 나타나고, 그 변경으로 원자가·명시적 수소·총전하가 어떻게 바뀌는지 미리 안내한다. 전하가 있는 구조는 교육 카드로 이동하기 전에도 캔버스에서 부호 배지로 보여야 한다.

수소 채우기는 전역 일괄 변환이므로 조립 콘솔에서 눈에 띄게 분리하고, 클릭 시 “추가될 H 수”와 “원자가를 계산하는 방식”을 미리 표시한다. 기본 버튼은 `수소 미리보기`이고, 확인 후 `채우기`를 누르게 한다. 초심자의 골격식 연습에는 암시적 수소 표시 토글을 제공하되, 실제 원자 데이터와 시각 표현을 혼동하지 않도록 범례를 붙인다.

### 3.5 선택, 삭제, 실행취소

선택은 단일·Shift 다중·박스 선택을 유지한다. 다만 모든 선택 결과를 캔버스의 색 테두리, 개수 칩, 컨텍스트 바에 동시에 보여 주고, 4개 이상 선택되어 측정 문법을 벗어나면 “선택 집합 편집” 상태임을 명확히 한다.

삭제는 두 가지 의미를 메뉴에서 명시한다. `선택만 삭제`는 선택한 원자·결합만 지우며, `조각까지 정리`는 앵커에서 떨어진 부분을 함께 정리한다. 우클릭/지우개로 호출한 경우에도 커밋 뒤 토스트에 실제 삭제 범위와 `되돌리기` 버튼을 넣는다. 대규모 삭제, 고리 삽입, 수소 일괄 채우기에는 **재실행(Redo)** 을 반드시 지원하고, 최근 5개 작업을 짧은 히스토리로 노출한다.

## 4. 플랫폼별 조작 명세

### 4.1 데스크톱

데스크톱은 포인터 정밀도와 단축키를 활용하되, 단축키를 알아야만 가능한 주 경로를 만들지 않는다. 마우스가 캔버스에 있을 때만 스페이스바 드래그를 임시 탐색으로 사용하고, 조립 상태에서는 클릭이 곧 커밋이라는 일관성을 유지한다. 카메라 회전은 탐색 상태에서만 기본 활성화하고, 조립 상태에서 드래그는 우선 결합 방향 또는 박스 선택으로 해석한다. 사용자가 탐색을 원할 때는 스페이스바를 누르거나 상단 탐색 아이콘을 선택한다.

| 입력 | 기본 동작 | 고급 동작 | 피드백 |
|---|---|---|---|
| 클릭/탭 | 현재 상태에 맞는 선택·미리보기 커밋 | — | 대상·결과를 120–180ms 안에 표시 |
| 드래그 | 2D: 결합 방향/기존 원자 연결, 선택: 박스 선택 | 스페이스바+드래그: 카메라 | 제스처 시작 시 미리보기로 역할을 고정 |
| 휠 | 줌 | 슬롯/후보 순환은 슬롯 링이 열렸을 때만 | 줌과 편집 동작이 충돌하지 않음 |
| R / Shift+R | 현재 고스트 회전 / 반대 회전 | — | 회전 각도와 새 첨부 위치를 라벨로 표시 |
| Delete / Backspace | 선택 삭제 확인 칩 표시 | Shift+Delete: 조각까지 정리 | 삭제 대상·개수와 Undo 제공 |
| Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z | 실행취소 / 재실행 | 히스토리 열기 | 조작 이름이 포함된 토스트 |

### 4.2 모바일·태블릿

모바일에는 호버·우클릭·작은 상단 툴바를 전제로 한 흐름을 두지 않는다. 조립 콘솔은 화면 하단 시트로 고정하고, 원소는 4개 큰 최근 칩과 `원소 더 보기`로 나눈다. 구조 단위·카탈로그·학습 노트는 같은 하단 시트 계열을 공유하되, 한 번에 하나만 열린다.

| 모바일 제스처 | 동작 | 설계 이유 |
|---|---|---|
| 원자 길게 누르기 | 슬롯 링과 원자 컨텍스트 메뉴 열기 | 호버 없이 유효한 결합 자리 확인 |
| 슬롯 탭 | 고스트 커밋 | 손가락이 앵커를 가려도 안정적 |
| 두 손가락 핀치/드래그 | 줌/탐색 | 한 손가락 조립과 분리 |
| 화면 하단 `선택` 버튼 | 선택 모드 전환·올가미 시작 | 작은 원자에서 다중 선택 실패 감소 |
| 흔들기 금지, 길게 누른 Undo | 최근 조작 확인 | 우발 조작과 OS 제스처 충돌 방지 |

모든 터치 대상은 시각적 원자 반지름과 무관하게 최소 44 CSS px의 투명 히트 영역을 갖되, 인접 후보가 겹칠 때는 후보 선택기를 표시한다. 모바일 조립은 작은 구조를 만들 때마다 전체 화면이 흔들리지 않도록, 카메라 자동 맞춤은 새 조각 시작·큰 구조 단위 삽입·사용자 요청 때만 수행한다.

### 4.3 키보드와 보조기술

키보드 사용자는 캔버스에서 원자를 순서대로 순환하며, 현재 원자와 연결 가능 자리·선택 상태를 읽을 수 있어야 한다. 단순히 캔버스만 포커스 가능하게 두는 것으로는 부족하다.

| 기능 | 키보드 명세 | 스크린리더·텍스트 대안 |
|---|---|---|
| 원자 이동 | Tab/Shift+Tab 또는 방향키로 인접 원자 순환 | `C2, 산소 O3에 단일결합, 형식전하 −1`처럼 구조적으로 읽기 |
| 재료 선택 | Alt+1~4 최근 원소, Alt+M 구조 단위 | 선택 재료·단축키·현재 모드 안내 |
| 슬롯 선택 | Enter로 슬롯 링, 방향키로 슬롯, Enter로 커밋 | “3개 중 2번째, tetrahedral, 결합 가능” |
| 결합 편집 | 두 원자 선택 후 B, 결합 선택 후 1/2/3/A | 변경될 차수·원자가 경고를 커밋 전 공지 |
| 삭제·되돌리기 | Delete, Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z | 실제 제거 원자 수·Undo 가능 상태 안내 |

3D 캔버스에는 항상 동기화된 **구조 트리**와 선택 요약을 제공한다. 색만으로 원소·전하·오류를 전달하지 않고, 원소 기호·전하 부호·패턴 또는 텍스트 라벨을 같이 사용한다. 모션은 `prefers-reduced-motion` 환경에서 즉시 상태 변화와 텍스트 확인으로 대체한다.

## 5. 오류 방지와 신뢰 기준

### 5.1 커밋 전 검증

불가능한 조작은 사후 에러보다 사전 미리보기에서 막아야 한다. 원자가 포화, 같은 원자 연결, 이미 존재하는 결합, 지나치게 먼 결합, 교육용 구조 골격의 UFF 제한은 고스트 상태에서 구분해 보여 준다. 오류 메시지는 이유 하나와 다음 행동 하나만 제공한다.

| 상황 | 나쁜 피드백 | 바꿀 피드백 |
|---|---|---|
| 원자가 포화 | “결합할 수 없습니다” | “C3의 결합차수 합은 4입니다. 다른 원자를 고르거나 기존 결합차수를 바꾸세요.” |
| 비공유쌍 슬롯 | “실패” | “보라색은 비공유 전자쌍 자리입니다. 원자는 초록 결합 슬롯에만 붙일 수 있습니다.” |
| 결합 대상이 멂 | “너무 멉니다” | “고리 닫기는 두 끝을 가까이 배치한 뒤 시도하세요. 자동 연결은 현재 거리에서 허용하지 않습니다.” |
| 가지치기 삭제 | “3개 원자 제거” | “선택한 C4를 지우면 연결이 끊긴 O5–H6도 함께 제거됩니다. `선택만 삭제`로 바꿀 수 있습니다.” |
| 수소 채우기 | “완료” | “빈 원자가에 H 6개를 추가합니다. 이 변화는 Undo로 되돌릴 수 있습니다.” |

### 5.2 조작감 규칙

* 미리보기는 120ms 이내에 나타나고, 클릭 커밋은 180ms 이내에 시작한다. 고리 삽입·자동 완화처럼 시간이 필요한 조작은 즉시 고정된 프리뷰를 보여 주고 비동기 진행 상태를 표시한다.
* 카메라 자동 이동은 사용자가 대상을 잃었을 때만 일어난다. 원자 하나 추가·선택·전하 변경마다 화면을 재정렬하지 않는다.
* 모든 파괴적 변환은 한 번의 Undo로 전부 되돌아가야 하며, Undo 이후 Redo가 가능해야 한다.
* 같은 결과를 얻는 입력은 데스크톱·터치·키보드에서 모두 존재해야 한다. 단축키는 속도 향상 수단이지 기능의 유일한 경로가 아니다.
* 교육 모델 한계는 오류처럼 보이지 않게, 적용 가능한 조작·판정만 제공하고 나머지는 “이 구조에서는 해석하지 않음”으로 명시한다.

## 6. 구현 우선순위

### P5-A — 조립 콘솔과 선택 컨텍스트 바

가장 먼저 상단 도구 모음을 재구성한다. 기존 `state.tool`과 원자/고리 고스트·원자가 검증 로직은 유지하고, 이를 새 표면에 매핑한다. 상단의 기능을 제거하는 작업이 아니라, 전역 제어와 현재 선택의 제어를 분리하는 작업이다.

| 구현 항목 | 기존 코드 영향 | 수용 기준 |
|---|---|---|
| 전역 헤더 축소 | `index.html` 도구 배치·CSS | 첫 화면에서 활성 재료와 조립/선택 상태가 한눈에 보임 |
| 조립 콘솔 | 팔레트·구조 단위·2D/3D 전환을 새로운 컨테이너에 배치 | 최근 원소 4개와 `더 보기`만으로 원소 선택 가능 |
| 선택 컨텍스트 바 | `state.selection`, `pendingBond`, 전하·삭제·복제 이벤트 | 원자 1개/2개/결합/다중 선택마다 유효 행동만 표시 |
| 되돌리기/재실행 | `undoStack` 확장, `redoStack` 추가 | 모든 파괴적 조작이 Undo/Redo로 왕복 가능 |
| 의미 있는 토스트 | `toast()` 확장 | 삭제·수소 채움·고리 삽입 뒤 `되돌리기` 액션 제공 |

### P5-B — 2D 직접 스케치 MVP

2D를 단순 보기 전환이 아니라 기본 저작 면으로 강화한다. 먼저 “빈 곳 탭으로 새 조각 시작”, “원자에서 드래그로 방향 지정 추가”, “결합 탭의 인라인 속성 메뉴”를 구현한다. 자유형 배치가 화학적으로 불가능한 결합을 우회하도록 만들지 말고, `canBond`, `attachAtom`, `bondDistanceOk`, `aromatize`를 그대로 재사용한다.

| 구현 항목 | 수용 기준 |
|---|---|
| 빈 캔버스 새 조각 시작 | 선택 원소로 독립 원자가 생성되고 Undo 한 번으로 제거됨 |
| 드래그 방향 결합 | 드래그 방향과 가까운 레이아웃에 새 원자가 생기며 결합 길이는 모델 규칙에 맞음 |
| 기존 원자 연결 드래그 | 두 원자가 유효하면 고리 닫기 미리보기 후 연결, 아니면 이유를 사전 표시 |
| 결합 속성 팝오버 | 유효 차수만 선택 가능하고 차수 변경 전후 원자가·혼성화가 보임 |
| Sketch/Model 명칭 | 토글 텍스트가 현재 상태와 다음 상태를 혼동시키지 않음 |

### P5-C — 3D 슬롯 링과 터치 조작

3D에서는 현재 고스트의 과학적 장점을 유지하면서 발견성을 높인다. `slotKinds`, `previewAttach`, `idealDirection`은 재사용하고, 슬롯 순환 상태를 화면의 방사형 링으로 보여 준다. 터치는 길게 누르기 → 슬롯 링 → 슬롯 탭으로 분리한다.

| 구현 항목 | 수용 기준 |
|---|---|
| 슬롯 링 | 앵커 주변의 모든 결합 가능/불가능 슬롯을 동시에 표시하고 현재 슬롯을 명확히 강조 |
| 후보 원자 선택기 | 겹친 원자에서 잘못된 앵커를 고르지 않고 후보를 전환 가능 |
| 터치 제스처 | 한 손가락 조립과 두 손가락 탐색이 충돌하지 않음 |
| 큰 히트 영역 | 44px 목표 영역에서 인접 원자 후보를 예측 가능하게 분리 |
| 고리 회전 핸들 | R 키 없이도 회전 결과와 첨부 위치를 확인·선택 가능 |

### P5-D — 접근성·학습 모드와 관찰 데이터

마지막으로 구조 트리, 키보드 슬롯 링, 스크린리더 안내, 익명화된 조작 실패 이벤트를 추가한다. 이 단계는 제품화에 중요하지만 P5-A~C의 핵심 조작이 안정된 뒤 진행한다. 수집 이벤트는 “어떤 학생이 원자가 포화에서 멈추는가”, “어떤 도구가 취소되는가”, “얼마나 자주 Undo되는가”처럼 UX 개선에 필요한 최소 정보만 남긴다.

## 7. 테스트와 검증 계획

### 7.1 단위·계약 테스트

현재 `node --test` 기반 회귀 체계에 다음을 추가한다.

| 범주 | 테스트 예 |
|---|---|
| 조작 상태 | 조립/선택/탐색 전환이 고스트·결합 대기·선택 상태를 의도적으로 유지 또는 해제하는지 |
| Undo/Redo | 원자 추가, 결합차수 변경, 고리 삽입, 가지치기 삭제, 수소 채움이 정확히 왕복하는지 |
| 2D 직접 스케치 | 빈 곳 시작, 드래그 방향, 결합 드래그가 동일한 모델 규칙·원자가 검사 경로를 쓰는지 |
| 3D 슬롯 | 슬롯 링의 각 항목이 `slotKinds`와 일치하고 비공유쌍에는 커밋하지 않는지 |
| 전하 | 전하 변경이 선택 컨텍스트에만 나타나며 직렬화·MOL 내보내기를 보존하는지 |
| 접근성 | 각 컨텍스트 상태의 포커스 순서, 키보드 대체 행동, `aria-live` 확인 문구가 있는지 |

### 7.2 실제 브라우저 시나리오

데스크톱·모바일·키보드 각각에서 다음 시나리오를 자동화하고, 매 릴리스에서 수동 검토한다.

1. 빈 2D 캔버스에서 에탄올 골격을 만들고 O–H를 추가한 뒤 전체 행동을 Undo/Redo 한다.
2. 선택한 두 탄소를 연결해 고리를 닫고, 고리 삽입 회전을 바꾼 뒤 결과를 취소한다.
3. 3D에서 한 이웃을 가진 탄소에 두 번째 원자를 서로 다른 슬롯에 붙여 배치 방향이 달라짐을 확인한다.
4. 원자가가 찬 탄소, 비공유쌍 슬롯, 너무 먼 결합에서 잘못된 커밋이 일어나지 않고 다음 행동이 안내되는지 확인한다.
5. 375px 폭 터치 환경에서 원소 선택, 길게 누른 슬롯 링, 결합, 삭제, Undo/Redo가 가능한지 확인한다.
6. 키보드만으로 원자 이동, 재료 선택, 슬롯 커밋, 결합 변경, 삭제, Undo/Redo를 완수한다.
7. 감소된 모션에서 기능 확인이 애니메이션이 아니라 텍스트와 포커스 이동으로 전달되는지 확인한다.

### 7.3 성과 측정

출시 전 사용성 테스트에서는 “학생이 아는가”가 아니라 다음을 측정한다. 첫 원자 추가까지의 시간, 결합 생성 성공률, 실수 후 복구 시간, 도구 전환 횟수, Undo 비율, 원자가 오류 반복률, 과업 성공 후 자기 설명의 정확도가 핵심이다. P5-A 이후에는 조립 과업을 수행하는 초심자 5~8명과 유기화학 수강생 5~8명을 대상으로 짧은 관찰 테스트를 실시하고, 실패 패턴이 안정될 때까지 P5-B로 넘어가지 않는다.

## 8. 권장 시작점

코드 구현의 첫 스프린트는 **P5-A 조립 콘솔 + 선택 컨텍스트 바 + Redo**로 한정한다. 이 단계는 과학 모델을 바꾸지 않고도 현재의 다층 툴바와 모드 전환 부담을 줄이며, 이후 2D 드래그·3D 슬롯 링이 들어갈 안정적 표면을 만든다. P5-B의 새 스케치 제스처는 그다음에 별도 기능 플래그로 도입해, 기존 조립 경로와 학습 테스트를 손상시키지 않고 비교할 수 있게 한다.
