# 미션 엔진 + 신뢰등급 배지 (S1)

**작성일** 2026-08-12
**범위** mol-craft를 조립 샌드박스에서 **개념 학습 플랫폼**으로 전환하는 첫 단계.
**전제 문서** `.textbook-kb/orgchem-short-course-13e/molcraft-gap.md` (표현력 격차 실측), `INDEX.md`(18장 라우팅), `concept-map.md`(개념 의존 그래프)

---

## 1. 문제

현재 mol-craft는 도구는 완성돼 있으나 **"무엇을 왜 하는지"가 없다.**

- 접속하면 메탄이 뜨고, 학생은 할 일을 모른다. 교육 콘텐츠는 프리셋 10종의 한 줄 `note`가 전부다.
- 교재 18장과 앱 사이에 경로가 하나도 없다.
- `총 에너지 12.3 kcal/mol` 같은 수치가 해석 근거 없이 노출된다. 위상이 다른 분자끼리 총에너지를 비교하는 **오학습을 앱이 막지 않는다.**

## 2. 목표와 성공 기준

목표: **교재의 대표 개념 10개를, 학생이 직접 조작하고 검증하며 이해하도록 만든다.**

성공 기준(구현 완료 판정):
1. 시드 미션 10개가 각각 정답 상태에서 통과하고, 지정된 오답 상태에서 지정된 진단 메시지를 낸다 — `test/mission.test.js`로 검증.
2. 힌트는 항상 한 단계씩만 열리고, 정답 힌트는 3회 시도 전에는 열리지 않는다.
3. 총에너지 표시에 신뢰등급 배지가 항상 붙는다. 위상이 다른 두 구조의 총에너지 차이는 **UI에 표시되지 않는다.**
4. 미션 진행 상태가 새로고침 후에도 복원된다(localStorage).
5. 미션 중에도 기존 조립 도구가 그대로 동작한다(샌드박스 유지).

**범위 밖(명시적 제외):** 반응 메커니즘 시뮬레이션, 곡선화살표, pKa·반응열, 서버·로그인·계정, 모바일 터치 조작, 챕터 맵 화면, 프리셋 확충. 각각 후속 스펙(S2~S6)에서 다룬다.

## 3. 왜 지금 이것부터인가

미션 엔진은 **신규 화학 코드를 한 줄도 요구하지 않는다.** 채점에 필요한 술어가 전부 기존 함수다.

| 판정 | 기존 함수 |
|---|---|
| 분자식 | `snap.formula()` |
| 구조 동일성 | `uff.topologyKey()` |
| 거리·결합각·이면각 | `model.measure()` |
| 에너지·항별 분해 | `uff.energy().byType` |
| 문제 원자 | `snap.stability()` |
| 고리 | `model.findRings()` |
| 이웃·결합차수 | `model.neighbors()`, `model.bondOrderSum()` |
| 배좌 프로파일 | `uff.scanDihedral()` |
| 시작구조 직렬화 | `io.encodeState()` / `decodeState()` |

반대로, CIP(R/S)·NMR 신호수 같은 후속 기능(S3·S4)을 먼저 만들면 **소비 경로가 없어 아무도 쓰지 않는 계산기**로 남는다. 엔진이 먼저 있으면 그 기능들이 즉시 판정형 미션으로 환원된다.

## 4. 아키텍처

`src/app.js`는 이미 1305줄이다. **미션 코드는 여기에 넣지 않는다.**

| 새 파일 | 책임 | 의존 | DOM |
|---|---|---|---|
| `src/mission.js` | 술어 평가기, 채점, 진단 선택, 힌트 해금 | model·snap·uff·io | 없음 |
| `src/mission-data.js` | 시드 미션 10개 선언형 데이터 | 없음 | 없음 |
| `src/trust.js` | 수치 신뢰등급 판정 | uff | 없음 |
| `src/mission-ui.js` | 미션 패널 렌더 + 진도 저장 | mission·trust | 있음 |

`mission.js`·`trust.js`는 순수 함수만 노출한다. DOM을 모르므로 `node --test`에서 그대로 테스트된다(기존 `test/*.test.js`와 동일한 방식).

**`app.js` 변경은 세 지점뿐이다.**
1. 우측 패널에 `mission-ui`의 마운트 지점(`<section id="mission">`) 추가와 초기화 호출.
2. 미션이 요구하는 시작구조를 로드하는 콜백 — 기존 `loadPreset()` / `decodeState()`를 그대로 부른다.
3. 채점에 필요한 현재 상태(`state.mol`, `state.selection`)를 읽는 게터 — `mission.js`는 `app`의 상태 객체를 직접 참조하지 않고 이 게터로만 받는다.

미션 UI는 화면을 점유하지 않는다. **우측 패널의 한 섹션으로 얹힌다** — 미션 중에도 학생이 자유롭게 조립할 수 있어야 하고, 미션을 끝낸 뒤에도 그 구조를 계속 가지고 놀 수 있어야 한다.

### 데이터 흐름

```
미션 선택
  → start 상태 로드 (app 콜백)
  → [predict/classify] 학생이 답 확정 → 잠금 → probe 실행 → 결과 대비
  → [build/measure]   학생이 도구로 조작 → "제출"
  → mission.evaluate(mol, mission, ctx)
  → { pass, failed, diagnostic, trust } → mission-ui 렌더
  → 진도 localStorage 기록
```

## 5. 미션 스키마

```js
{
  id: 'ch02-butane-anti',           // 고유. 진도 저장 키
  chapter: 2,
  concept: '배좌와 스트레인',
  type: 'build',                     // 'build' | 'measure' | 'predict' | 'classify'
  title: '부탄을 anti 배좌로 만들어라',
  brief: 'σ 결합은 자유롭게 회전한다. 그중 가장 안정한 배치를 찾아라.',

  start: { preset: 'butane' },       // 또는 { state: '<encodeState 문자열>' }

  // predict/classify 전용
  choices: [{ id: 'a', label: '…' }, { id: 'b', label: '…' }],
  answer: 'b',
  probe: { … },                      // 답 확정 후 엔진이 실행할 계산 (§7)

  // build/measure 전용
  check: { all: [
    { formula: 'C4H10' },
    { topologyMatches: 'start' },
    { dihedral: [0, 1, 2, 3], within: [150, 210] },
  ]},

  diagnostics: [
    { when: { dihedral: [0, 1, 2, 3], within: [40, 80] },
      message: 'gauche 배좌입니다. anti는 이면각 180° — 메틸 두 개가 정반대를 봐야 합니다.' },
  ],

  hints: [
    '배좌는 σ 결합의 회전으로만 바뀝니다. 결합을 끊을 필요가 없습니다.',
    '중심 C–C 결합을 사이에 둔 이면각을 보세요.',
    '원자 4개를 C1–C2–C3–C4 순서로 선택하면 이면각 슬라이더가 활성화됩니다.',
    '목표 이면각은 180°입니다.',
  ],

  trust: 'geometry',                 // 'geometry' | 'relative' (§8)
}
```

### 술어 목록

기존 함수의 얇은 래퍼다. **새 화학 로직은 없다.**

| 술어 | 인자 | 구현 |
|---|---|---|
| `formula` | 문자열 | `snap.formula(mol) === value` |
| `topologyMatches` | `'start'` \| 상태 문자열 | `uff.topologyKey()` 비교 |
| `distance` | `[i,j]`, `within: [min,max]` | `model.measure()` |
| `angle` | `[i,j,k]`, `within` | `model.measure()` |
| `dihedral` | `[i,j,k,l]`, `within` | `model.measure()` — 부호 순환 정규화 후 비교 |
| `energyDelta` | `within` | `uff.energy()` — **동일 topologyKey 강제**(§8) |
| `strainByType` | `type: 'angle'\|'torsion'\|'vdw'`, `within` | `uff.energy().byType` |
| `noSevere` | — | `snap.stability()`에 danger 없음 |
| `ringCount` | 정수 | `model.findRings().length` |
| `ringSize` | 정수 배열 | `model.findRings()` 크기 집합 |
| `hasGroup` | `{ center, neighbors: [{el, order}] }` | `neighbors`+`bondOrderSum` 국소 매칭 |
| `selectionEquals` | 원자 인덱스 배열(순서 무관 집합) | 학생의 현재 선택이 지정 원자들과 일치 — `measure` 미션이 "올바른 대상을 쟀는지" 확인 |
| `answerEquals` | 선택지 id | predict/classify/measure 답 비교 |

조합자는 **`all` / `any` / `not` 셋뿐이다.** 그 이상은 필요해질 때 추가한다.

**이면각 비교 규칙:** `measure()`가 반환하는 값은 −180~180이다. `within: [150, 210]`처럼 ±180을 넘는 구간은 360 법으로 정규화해 판정한다. anti 배좌 판정에 반드시 필요하다.

**원자 인덱스 안정성:** `check`의 인덱스는 `start` 상태의 인덱스를 가리킨다. `build` 미션에서 학생이 원자를 **추가**하면 기존 인덱스는 보존되지만(`addAtom`은 뒤에 붙는다), **삭제**하면 밀린다. 따라서 원자 삭제가 정답 경로에 포함된 미션은 인덱스 술어(`angle`/`dihedral`) 대신 `hasGroup`·`formula` 같은 인덱스 무관 술어를 쓴다. 시드 10개는 이 규칙을 지킨다.

## 6. 네 가지 미션 유형

| 유형 | 흐름 | 채점 |
|---|---|---|
| **build** | 시작구조 → 조립 도구로 조작 → `제출` | `check` 술어 트리 |
| **measure** | 시작구조 → 기존 `선택 측정` 도구로 대상을 재고 → 그 값의 의미를 선택지에서 고름 | `selectionEquals` + `answerEquals` |
| **predict** | 선택지에 먼저 답함 → **잠금** → `probe` 실행 → 결과 대비 | `answerEquals` |
| **classify** | 구조 제시 → 라벨 선택 → 즉시 채점 | `answerEquals` |

**`measure`는 두 단계로 채점한다.** 구조가 이미 주어져 있으므로 구조만 검사하면 아무 조작 없이 통과한다. 따라서 ① 학생이 **올바른 원자를 선택해 실제로 쟀는지**(`selectionEquals`)와 ② 그 수치가 무엇을 뜻하는지(`answerEquals`)를 함께 본다. 예: 6번 미션은 벤젠의 인접 C–C 두 쌍을 선택하게 하고, "두 값이 같다 / 하나는 1.34 하나는 1.54" 중에서 고르게 한다.

**`predict`가 이 스펙의 핵심이다.** 답을 먼저 확정시키고 잠근 뒤 계산을 돌려야, 학생의 오개념이 본인 눈앞에서 깨진다(predict–observe–explain). 계산 결과를 먼저 보여주면 학습 효과가 사라지므로, 잠그기 전에는 `probe` 결과를 **어떤 형태로도 노출하지 않는다.**

## 7. `probe` — predict 미션의 스크립트 계산

`predict` 미션은 답 확정 후 엔진이 정해진 계산을 실행한다. 학생이 직접 조작할 필요가 없다.

```js
probe: {
  kind: 'minimize' | 'scanDihedral' | 'measure',
  states: ['<start>', '<alt>'],      // 1개 또는 2개. 2개면 나란히 비교
  args: { … },                       // scanDihedral의 idx·stepDeg 등
  report: [                          // 학생에게 보여줄 항목
    { label: 'α 아노머', value: 'energy' },
    { label: 'β 아노머', value: 'energy' },
  ],
}
```

2-state probe는 `trust` 규칙(§8)의 검사를 받는다. 위상이 다른 두 상태의 **총에너지 차이는 리포트할 수 없다.**

## 8. 신뢰등급 (`trust.js`)

학습 플랫폼의 신뢰는 "무엇을 모르는지 말하는 것"에서 나온다. 모든 수치에 등급을 붙인다.

| 등급 | 대상 | UI 처리 |
|---|---|---|
| 🟢 `geometry` | 결합각·결합길이·이면각·좌표 거리 | 그대로 표시 |
| 🟡 `relative` | **동일 `topologyKey` 내부**의 배좌 상대에너지 | 표시 + "정성 비교용 — UFF는 배좌 장벽을 과대평가합니다" 병기 |
| 🔴 `blocked` | 위상이 다른 두 구조의 총에너지 차이, pKa, 반응 에너지, 전이상태 | **표시하지 않고** 사유 문구로 대체 |

### 강제 지점 (선언이 아니라 코드)

1. `energyDelta` 술어와 2-state `probe`는 두 상태의 `topologyKey`를 비교한다. 다르면 **채점 실패가 아니라 미션 데이터 오류로 `throw`** 한다 — 학생 잘못이 아니라 저작 잘못이므로, 테스트에서 잡혀야 한다.
2. 총에너지 패널(`#total`)에 등급 배지를 상시 노출한다.
3. UFF 과대평가 항목(부탄 syn 장벽 등)은 `relative` 등급 문구에 문헌값 범위를 함께 적는다. 근거: `test/validation.test.js:92-94`, `molcraft-gap.md §4`.

**두 배좌 장벽을 서로 비교하는 경우**(예: 에틸렌의 회전 장벽 vs 에탄의 회전 장벽)는 각각이 자기 위상 내부의 상대에너지이므로 허용하되, 🟡 등급과 "각 분자 내부의 상대값끼리 비교하는 것이며 절대 수치는 신뢰하지 마십시오"라는 문구를 함께 낸다.

## 9. 오답 진단과 힌트

**"틀렸습니다"는 학습 가치가 0이다.** 필요한 것은 무엇을 오해했는지다.

- 채점 실패 시 `diagnostics`를 선언 순서대로 검사해 **첫 매칭 메시지 하나만** 출력한다. 여러 개를 쏟으면 학생이 읽지 않는다.
- 매칭이 없으면 실패한 술어에 대응하는 일반 메시지를 낸다(예: `formula` 실패 → "분자식이 다릅니다: 목표 C₄H₁₀, 현재 C₄H₈").
- 진단 메시지는 `snap.stability()`가 지목한 원자의 기존 글로우 표시와 함께 뜬다. 새 시각화를 만들지 않는다.

**힌트 사다리 4단.** 한 번에 한 단계만 열린다.

1. 개념 상기 — "무엇을 아는지"
2. 어디를 볼지 — 주목할 원자·결합
3. 구체 조작 — 어떤 도구를 어떻게
4. 정답

4단(정답)은 **시도 3회 이후에만** 해금된다. 즉시 정답을 열면 미션이 무의미해지고, 아예 막으면 학생이 이탈한다.

## 10. 진도 저장

```js
localStorage['molcraft:progress'] = {
  'ch02-butane-anti': { status: 'passed', attempts: 2, hintLevel: 1 },
  …
}
```

- 서버·계정 없음. **무료 유지 조건과 일치한다.**
- 실패한 미션은 오답 큐에 남고 미션 목록 상단에 다시 뜬다.
- 저장 실패(용량 초과·프라이빗 모드)는 무시한다 — 기존 `app.js:41 saveLocal()`과 동일한 정책. 저장 실패가 앱을 막아서는 안 된다.

| 4 | 2 | 고리 배좌 axial/equatorial | predict | 의자를 뒤집으면 axial 치환기는 어떻게 되는가 | 🟢 |
| 5 | 3 | π 결합이 회전을 막는다 | predict | 에틸렌과 에탄을 같은 각도로 비틀면 어느 쪽이 되돌아오는가 | 🟡 |
| 6 | 4 | 공명 → 결합길이 균등화 | measure | 벤젠의 여섯 C–C 결합 길이를 재라 (케쿨레 예상 1.34/1.54 vs 실제 균등) | 🟢 |
| 7 | 6 | E2의 anti-periplanar 요구 | measure | trans-1,2-이치환 사이클로헥세인에서 두 이탈기의 이면각을 재라 | 🟢 |
| 8 | 8 | 고리 크기와 각 스트레인 | predict | 에폭사이드와 테트라하이드로피란 중 어느 C–O–C 각이 이상각에서 더 벗어나는가 | 🟢 |
| 9 | 9 | 친핵성 첨가 sp²→sp³ | build | 카보닐 탄소에 원자를 붙이고 각도가 120°→109.5°로 바뀌는 것을 확인하라 | 🟢 |
| 10 | 16 | 아노머와 부분입체 | predict | α-글루코스와 β-글루코스 중 어느 쪽이 안정한가 (전-equatorial) | 🟡 |

유형 분포: predict 5 · build 2 · measure 2 · classify 1 — 네 유형이 모두 실제로 쓰인다.

### 의도적으로 제외한 장

**Ch5(입체화학) · Ch10(아마이드) · Ch12(스펙트럼) · Ch13(헤테로고리) · Ch17(단백질)**은 이번 시드에 넣지 않는다. 현재 엔진으로는 **틀리게 가르치게 되기 때문이다.**

- Ch5: CIP·R/S 판정 코드가 전혀 없다(`molcraft-gap.md` C-3).
- Ch10·17: 아마이드 N이 sp³로 남아 평면이 되지 않는다(C-4).
- Ch13: `aromatize()`가 피리딘·피롤·푸란을 전부 놓치고, 피롤 N에 **비공유쌍 자리를 잘못 표시한다**(C-4b, 실측 확인). 개념과 정반대다.
- Ch12: NMR/IR 판정기가 없다.

이 장들은 S2(화학 정확성 복구)·S3·S4 완료 후 미션을 추가한다.

### 8번 미션이 각도를 재는 이유

에폭사이드와 THP는 **위상이 다르다.** 총에너지나 `byType.angle` 값을 직접 비교하면 §8의 🔴에 해당한다. 대신 각 분자의 C–O–C 결합각을 재서 이상각(sp³ 109.5°)에서의 편차를 본다 — 순수 기하량이므로 🟢이고, "고리가 작을수록 각 스트레인이 크다"는 개념을 정확히 전달한다.

## 12. 테스트 (`test/mission.test.js`)

기존 `node --test` 스위트에 추가한다. 별도 러너를 도입하지 않는다.

1. **술어 단위** — 12개 술어 각각의 통과/실패 케이스.
2. **이면각 정규화** — `within: [150, 210]`이 −170°를 통과시키는지.
3. **시드 미션 왕복** — 미션 10개 각각에 대해 골든 정답 상태를 넣으면 통과하고, 지정된 오답 상태를 넣으면 **지정된 진단 메시지**가 나오는지. 정답/오답 상태는 `encodeState` 문자열로 테스트 픽스처에 고정한다.
4. **힌트 해금** — 시도 1·2회에서는 4단이 잠겨 있고 3회 후 열리는지.
5. **신뢰등급 강제** — 위상이 다른 두 상태로 `energyDelta` 술어나 2-state `probe`를 선언한 미션을 로드하면 `throw` 하는지.
6. **스키마 검증** — 알 수 없는 술어 이름, 존재하지 않는 `answer` id, 힌트 4단 미만이면 로드 시 실패하는지.

3번이 회귀 방어의 핵심이다. UFF나 `snap` 쪽을 고쳤을 때 미션이 조용히 깨지는 것을 여기서 잡는다.

## 14. UI 배치

우측 패널에 `미션` 섹션을 추가한다. 기존 섹션(`총 에너지`·`항별 분해`·`선택 측정`·`이면각 회전`·`최적화 리플레이`·`VSEPR 상태`) 위에 놓는다.

- 챕터 드롭다운 → 미션 목록(진행 상태 아이콘) → 선택 시 진행 카드로 전환
- 진행 카드: 제목 · 설명 · (유형별 입력) · `제출` · `힌트` · 진단 메시지 영역
- **전체화면 모드를 만들지 않는다.** 미션은 얹히는 레이어이고, 3D/2D 뷰어와 모든 도구는 그대로 살아 있다.
- 총에너지 패널에 신뢰등급 배지를 추가한다(미션과 무관하게 상시).

## 15. 후속 스펙과의 관계

| | 스펙 | S1과의 관계 |
|---|---|---|
| S2 | 화학 정확성 복구 (방향족 π기여 인식·방향족 원자가 회계·`charge` 필드·공액 sp²) | S1과 **병렬 가능**. 완료 시 Ch10·13·17·18 미션 해금 |
