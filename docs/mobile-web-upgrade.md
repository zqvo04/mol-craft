# Mol-Craft 모바일 웹 업그레이드 설계

## 1. 제품 정의와 설계 전제

Mol-Craft의 모바일 버전은 데스크톱 편집기를 좁은 화면에 축소한 형태가 아니라, 학생이 수업 전후의 짧은 시간에 **구조를 읽고, 한 가지 가설을 조립으로 시험하고, 그 결과를 학습 노트로 연결하는 터치 우선 실험 환경**이어야 한다. 따라서 목표는 모든 분석 기능을 첫 화면에 유지하는 것이 아니라, 현재 과업에 필요한 한 가지 행동과 한 가지 설명을 화면에 안정적으로 제시하는 것이다.

현재 P5는 세 가지 작업 상태(탐색·조립·선택), 최근 원소, 슬롯 링, 선택 컨텍스트, Undo/Redo를 이미 갖추고 있다. 그러나 720px 이하에서 툴바는 단순 줄바꿈에 머물고, 3D 캔버스와 긴 인스펙터는 한 화면 안에서 경쟁한다. 모바일 업그레이드는 이 구조를 **상단 문맥 바 + 전체 화면 캔버스 + 하단 조립 시트 + 필요할 때만 열리는 학습 시트**로 재배치한다.

> 모바일의 핵심 과업은 “전체 기능을 보이게 하는 것”이 아니라 “지금의 조작이 성공했는지, 그리고 왜 그런지 즉시 이해하게 하는 것”이다.

## 2. 모바일 정보 구조

### 2.1 기본 화면

| 영역 | 역할 | 항상 보이는 정보 | 숨겨지는 정보 |
|---|---|---|---|
| 상단 문맥 바 | 현재 분자·저장 상태·빠른 복구 | 분자명, 동기화/오프라인 상태, Undo, Redo, 더보기 | 내보내기, 색상, 전체 프리셋, 공유 |
| 캔버스 | 2D 기본 조립 또는 3D 공간 관찰 | 현재 모드, 선택 재료, 원자가/전하 경고, 슬롯·고스트 | 장문의 설명, 수치 표 전체 |
| 하단 조립 시트 | 재료 선택과 현재 선택의 편집 | 탐색/조립/선택 탭, 최근 원소 4개, 구조 단위, 선택 컨텍스트 | 전체 원소표, 카탈로그 상세 |
| 학습 시트 | 과업 맥락과 교재 설명 | 한 줄 관찰·힌트·다음 행동 | 전체 분석 표·모든 학습 카드 |

상단 문맥 바는 `safe-area-inset-top`을 고려해 52~60 CSS px의 높이를 확보한다. 헤더의 내보내기·공유·색상·카탈로그 같은 저빈도 행동은 `더보기` 시트로 옮기며, 파괴적이지 않은 Undo/Redo만 항상 남긴다. 하단 조립 시트는 시스템 홈 인디케이터 위에 고정하고 `env(safe-area-inset-bottom)`만큼 여백을 더한다.

### 2.2 화면 상태와 전환

모바일은 한 번에 하나의 시트만 연다. 조립 시트·구조 단위·카탈로그·학습 노트가 중첩되면 캔버스가 가려지고 뒤로 가기 흐름이 불명확해지므로, 새 시트가 열리면 이전 시트는 상태만 보존하고 닫는다. 시트는 화면 높이의 30%, 58%, 88% 세 단계로만 스냅하며, 아래로 드래그해 닫기보다 상단의 명시적 닫기와 시스템 뒤로 가기를 모두 지원한다.

| 상태 | 캔버스 | 하단 시트 | 학생에게 보이는 다음 행동 |
|---|---|---|---|
| 탐색 | 3D 기본, 한 손가락 회전 | 30% 접힘 | “원자를 탭해 정보 보기” |
| 2D 조립 | 2D 기본, 방향 고스트 | 58% 열림 | “C/N/O/H를 고른 뒤 빈 곳 또는 원자를 탭” |
| 3D 조립 | 앵커·슬롯 링 강조 | 58% 열림 | “원자를 길게 눌러 결합 자리 선택” |
| 선택 편집 | 선택 윤곽·구조 트리 동기화 | 58% 열림 | “전하·결합·복제·삭제 중 하나 선택” |
| 학습 확인 | 캔버스는 고정·선택 강조 | 58% 학습 시트 | “관찰을 읽고 다음 실험으로 이동” |

### 2.3 2D 우선, 3D 확인 원칙

구조의 빠른 구성은 2D에서 시작한다. 빈 캔버스 탭은 새 조각, 원자에서의 짧은 드래그는 방향을 반영한 원자 추가, 선택한 두 원자는 결합 생성 후보가 된다. 3D는 배치·VSEPR·배좌·비공유전자쌍을 확인하는 면으로 사용한다. 이 구분은 3D 카메라 제스처가 조립과 충돌하는 문제를 줄이고, 학생이 골격식과 공간 표현을 혼동하지 않게 한다.

## 3. 터치 제스처 계약

모든 편집 제스처는 Pointer Events로 통합하고, `pointerType`에 따라 시각 피드백만 보강한다. 마우스 전용 hover·우클릭을 주 경로로 삼지 않으며, 터치 동작에는 같은 결과에 도달하는 화면 제어를 반드시 둔다. 설치형 PWA도 키보드·마우스·스타일러스 입력을 지원해야 하므로 입력 방식과 화면 폭을 같은 조건으로 취급하지 않는다.[3]

| 입력 | 탐색 상태 | 조립 상태 | 선택 상태 | 충돌 방지 규칙 |
|---|---|---|---|---|
| 한 손가락 탭 | 원자 정보 강조 | 2D: 추가/시작, 3D: 앵커 후보 선택 | 원자·결합 선택 | 실제 원자보다 큰 히트 영역을 쓰되, 후보가 겹치면 선택기를 표시 |
| 길게 누르기 280ms | 원자 요약 | 3D 슬롯 링 열기 | 원자 컨텍스트 열기 | 이동 10px 이상이면 길게 누르기 취소 |
| 한 손가락 드래그 | 3D 회전 또는 2D 패닝 | 2D: 결합 방향, 3D: 조작 취소 후 탐색 제안 | 박스 선택 | 제스처 시작 80ms 안에 역할 라벨을 표시 |
| 두 손가락 핀치·드래그 | 줌·카메라 이동 | 줌·카메라 이동 | 줌·카메라 이동 | 항상 탐색으로 해석해 조립 커밋과 분리 |
| 하단 시트 스와이프 | 시트 높이 변경 | 시트 높이 변경 | 시트 높이 변경 | 캔버스 가장자리 제스처와 겹치지 않도록 시트 핸들에서만 시작 |

중요 버튼·슬롯·후보 원자 컨트롤은 시각 크기와 별개로 **44×44 CSS px**를 목표 면적으로 설정한다. WCAG 2.2 AA의 최소 목표 크기는 24×24 CSS px이지만, 터치 정밀도가 낮고 순차 조작의 실패 비용이 큰 분자 조립에서는 강화 기준 44×44 CSS px을 제품 기준으로 삼는 것이 적절하다.[1] [2]

## 4. 학습 흐름과 오류 회복

모바일 세션의 기본 단위는 3~8분짜리 마이크로레슨이다. 첫 화면은 “오늘의 구조”와 하나의 관찰 질문을 제시하고, 학생은 2D에서 구조를 만들거나 프리셋을 바꾼 뒤 3D로 확인한다. 분석 패널의 모든 수치를 한꺼번에 노출하지 않고, 과업에 필요한 카드 한 장만 우선 노출한다. 예를 들어 카복실레이트 레슨에서는 `COO⁻ 공명`과 `IR 두 밴드` 카드만 먼저 보이고, 총에너지와 UFF 분해표는 `분석 더보기` 아래로 이동한다.

| 학습 순간 | 모바일 피드백 | 과학적 경계 |
|---|---|---|
| 원자·결합 추가 | “C1에 O를 단일결합으로 추가”와 Undo | 자동 최적화가 구조 의도를 바꾸지 않음 |
| 불가능한 결합 | 이유 하나와 대안 하나 | “원자가 포화”를 반응성·안정성 예측으로 확대 해석하지 않음 |
| 전하 변경 | 총전하·원자가 변화 미리보기 | pKa·용액 분포는 판정하지 않음 |
| 3D 전환 | 2D 골격이 공간에서 어떤 방향인지 하이라이트 | UFF 수치는 정성 비교임을 계속 표기 |
| 레슨 완료 | 만든 구조·핵심 관찰·다음 문제 | 정답 구조와 에너지 최저 구조를 동일시하지 않음 |

큰 삭제·수소 채우기·구조 단위 삽입은 즉시 확정하지 않는다. 하단 시트의 작은 확인 행에서 “무엇이 몇 개 바뀌는지”를 보여 주고, **적용**과 **취소**를 나란히 둔다. 일반 원자 추가와 전하 변경은 즉시 반영하되, 모든 결과 토스트에 5초간 Undo를 제공한다. 이는 조립의 직접성을 유지하면서 되돌리기 어려운 오류를 줄인다.

## 5. 접근성·성능·오프라인 요구사항

### 5.1 접근성은 별도 모드가 아니라 동일 기능의 대체 경로다

모바일 조립의 모든 결과는 터치·키보드·구조 트리에서 같아야 한다. 3D 캔버스의 원자·슬롯처럼 밀집된 공간적 대상은 44px 버튼을 무리하게 겹치게 하지 않고, 원자 후보 선택기와 구조 트리라는 동등한 대체 경로를 제공한다. 색은 원소·전하·위험도의 보조 단서일 뿐 유일한 전달 수단이 아니어야 하며, 전하 부호·원소 기호·짧은 텍스트 라벨을 함께 쓴다.

| 영역 | 요구사항 | 검증 방법 |
|---|---|---|
| 터치 대상 | 일반 제어·슬롯·후보의 목표 면적 44×44 CSS px, 최소 24×24 CSS px 준수 | 320·375·390·430px 폭에서 DOM 측정과 수동 탭 검증 |
| 포커스·구조 트리 | 캔버스 선택 상태와 트리 항목이 양방향 동기화, 명시적 포커스 고리 | TalkBack·VoiceOver 및 키보드 탭 순서 검증 |
| 상태 알림 | 조립 성공, 원자가 불가, Undo 가능, 오프라인 상태를 짧은 `aria-live` 문장으로 제공 | 같은 조작에서 중복 읽기·누락이 없는지 수동 점검 |
| 확대·글자 | 200% 텍스트 확대에서 가로 스크롤 없이 핵심 조립·Undo·학습 카드 사용 가능 | 브라우저 확대, 큰 글자, 가로·세로 화면 전환 테스트 |
| 모션 | `prefers-reduced-motion`에서 링·시트·캔버스 효과를 즉시 전환과 텍스트 피드백으로 대체 | OS 감소된 모션 에뮬레이션과 실제 기기 점검 |

### 5.2 성능 예산

현재 3Dmol.js CDN과 300개 분자 카탈로그, UFF 계산은 저가형 휴대기기에서 첫 입력 지연과 배터리 소모를 만들 수 있다. 모바일은 “모든 분자의 항상-고품질 렌더링”보다 조립 중의 일관된 반응성을 우선한다. PWA 품질 가이드가 시작 속도와 상호작용 반응성을 핵심으로 다루듯, Mol-Craft도 로드 이후뿐 아니라 탭·드래그·Undo가 등록되었다는 피드백을 즉시 보여야 한다.[3]

| 영역 | 모바일 정책 | 초기 수용 기준 |
|---|---|---|
| 초기 로드 | 앱 셸·기본 프리셋·핵심 CSS 우선, 3Dmol과 카탈로그 상세 이미지는 지연 로드 | 보통 4G 조건에서 첫 조립 가능 상태를 3초 내 목표로 측정 |
| 렌더링 | 조립 중에는 저해상도·낮은 안티앨리어싱, 조작 종료 180ms 뒤 품질 복구 | 탭·드래그 중 긴 프레임이 반복되지 않도록 Performance 패널 점검 |
| UFF | 추가·전하·선택 때 전체 최소화 금지, 명시적 최적화와 분석 시에만 계산 | 조립 커밋 뒤 카메라·Undo가 계속 반응 |
| 카탈로그 | 목록의 텍스트·식·태그 우선, 구조식은 뷰포트 진입 시 요청·재시도 | 오프라인에서도 저장된 항목과 기본 프리셋은 열림 |
| 메모리 | 큰 프리셋 전환 뒤 이전 3D 오브젝트·리스너·캐시 해제 | 10회 프리셋 전환 뒤 캔버스 성능 저하가 없음 |

성능 예산은 기기·네트워크 조건을 포함해 실제 측정으로 확정해야 한다. 위 숫자는 출시 기준이 아니라 첫 프로토타입의 관찰 목표이며, 저가형 Android와 최근 iPhone을 포함한 실측 결과로 조정한다.

### 5.3 점진적 PWA·오프라인 전략

PWA는 기능 목록이 아니라 **학습 세션을 잃지 않는 신뢰 전략**으로 도입한다. 서비스 워커는 앱 셸과 정적 학습 콘텐츠를 캐시해 연결이 끊겨도 기본 구조 조립과 최근 노트를 열 수 있게 하며, IndexedDB에는 사용자가 만든 구조 스냅샷·Undo 복구용 임시 상태·즐겨찾기를 저장한다. 서비스 워커는 별도 스레드에서 캐시 요청을 처리할 수 있어 UI 반응성을 유지하는 데도 도움이 되지만, 캐시 우선 전략은 오래된 콘텐츠를 돌려줄 수 있으므로 카탈로그·교재 카드의 버전 정책을 함께 설계해야 한다.[4]

| 단계 | 포함 범위 | 명시적으로 제외하는 범위 |
|---|---|---|
| **M-PWA 1: 복구 가능한 웹** | `manifest.webmanifest`, 앱 아이콘, 앱 셸 프리캐시, 맞춤 오프라인 화면, 로컬 구조 자동 저장 | 알림, 백그라운드 동기화, 계정 간 자동 병합 |
| **M-PWA 2: 선택적 설치** | 설치 안내를 학습 2회 완료 뒤에만 표시, 저장 공간·마지막 동기화·오프라인 배지 | 첫 방문 권한 요청, 강제 설치 배너 |
| **M-PWA 3: 계정 동기화** | 서버가 준비된 뒤 구조·진도 충돌 해결, 명시적 수동 동기화, 보류 작업 큐 | 서비스 워커가 장시간 UFF 계산을 수행하는 모델 |

기본 상태는 **local-first**로 유지한다. 네트워크가 없으면 사용자는 “오프라인—이 기기에 저장됨”이라는 상태를 보고 계속 조립할 수 있으며, 서버 동기화가 필요한 기능만 비활성화한다. 연결 회복 시에도 자동으로 구조를 덮어쓰지 않고, 마지막 수정 시각과 충돌 해결 선택지를 보여 준다. 설치된 앱이 오프라인에서 브라우저 기본 오류 페이지를 보이지 않도록 맞춤 대체 화면을 제공하는 것이 PWA 품질 기준에 부합한다.[3]

### 5.4 기술 경계와 출시 전제

Mol-Craft는 현재 정적 앱이므로 M-PWA 1까지는 기존 GitHub Pages 구조로 구현할 수 있다. 그러나 개인별 진도, 교사 과제, 공동 구조 편집, 유료 구독, 결제 후 권한 같은 기능은 인증·데이터베이스·서버 측 권한 검증이 필요하다. 이 기능들은 PWA 캐시와 별도의 플랫폼 단계로 다루며, 서비스 워커나 `localStorage`를 권한의 근거로 사용하지 않는다.

## 6. 구현 로드맵

### M0 — 측정 가능한 모바일 기준선

첫 단계에서는 새 기능을 추가하지 않는다. 320×568, 375×812, 390×844, 430×932 CSS px의 세로·가로 화면을 자동 캡처하고, 주요 버튼의 실제 목표 면적·가려진 캔버스 영역·시트 중첩·글자 확대 시 가로 스크롤을 기록한다. 이 기준선이 없으면 이후의 “모바일 개선”은 데스크톱 미리보기의 인상에 머물 수 있다.

### M1 — 모바일 셸과 정보 계층

`index.html`과 앱 상태에 `mobileSheet`·`mobileMode`를 추가한다. 기존 헤더의 저빈도 제어를 더보기 시트로 옮기고, 조립 콘솔을 안전 영역을 인지하는 하단 시트로 전환한다. 인스펙터는 독립 사이드바가 아니라 분석·학습 탭을 가진 시트가 되며, 2D/3D 캔버스는 남은 화면을 항상 차지한다. 이 단계는 P5의 상태·분자 모델·UFF 규칙을 바꾸지 않는 레이아웃 전환이다.

| 항목 | 주요 코드 영향 | 수용 기준 |
|---|---|---|
| 상단 문맥 바 | `index.html` 헤더·CSS, 빠른 행동 재배치 | 375px에서 분자명·Undo·Redo·더보기가 한 줄에 도달 가능 |
| 하단 조립 시트 | 새 시트 상태, `safe-area` CSS, 포커스 복귀 | 홈 인디케이터와 겹치지 않고 30/58/88% 스냅이 예측 가능 |
| 인스펙터 시트 | `aside`, 탭·시트 전환 | 조립 시 캔버스를 가리지 않고 필요할 때 분석·학습을 열 수 있음 |
| 시트 단일화 | 구조 단위·카탈로그·학습의 열림 상태 | 둘 이상의 모달/시트가 동시에 포커스를 빼앗지 않음 |

### M2 — 터치 우선 조립 안정화

M2에서는 Pointer Events 기반의 제스처 조정기를 도입한다. `pointerdown → move → up/cancel`을 하나의 제스처 상태로 묶고, 280ms 길게 누르기·10px 이동 취소·두 손가락 탐색 분리를 구현한다. 2D의 방향 드래그는 P5의 `attachAtom`과 `canBond`를 재사용하고, 3D 슬롯·후보 선택기는 시트나 캔버스 오버레이에서 44px 목표 면적을 보장한다.

| 항목 | 수용 기준 |
|---|---|
| 2D 조립 | 빈 곳 탭, 원자 드래그, 두 원자 결합이 스크롤·카메라 이동과 충돌하지 않음 |
| 3D 슬롯 | 길게 누르기 후 링이 열리고, 모든 슬롯·후보 버튼이 44px 목표 면적을 만족 |
| 실수 회복 | 조립·삭제·전하 변경 뒤 Undo가 항상 같은 화면 위치에서 사용 가능 |
| 선택 | 손가락으로 작은 원자를 고르기 어려우면 후보 선택기와 구조 트리가 같은 결과를 제공 |

### M3 — 학습 세션 최적화

M3는 화면을 예쁘게 만드는 단계가 아니라 교재 학습 흐름을 완성하는 단계다. 단원별 마이크로레슨을 “관찰 질문 → 2D 조립 → 3D 확인 → 한 장의 설명 카드 → 다음 행동”으로 정의하고, 분석 수치 전체는 보조 시트에 둔다. 사용자 구조는 로컬 자동 저장하며, 레슨 완료·중단·재시도를 최소 단위로 복원한다.

### M4 — PWA 신뢰성과 성능

M4에서 앱 셸·기본 프리셋·핵심 학습 카드를 프리캐시하고, 사용자가 만든 구조·즐겨찾기·최근 레슨을 IndexedDB에 저장한다. 3Dmol 지연 로드, 카탈로그 이미지의 뷰포트 지연 로드, UFF 계산의 명시적 실행을 포함해 저가형 기기에서의 상호작용 예산을 검증한다. 설치 안내는 사용자가 최소 두 번의 학습 세션을 완료한 뒤에만 노출한다.

### M5 — 계정·동기화·수업 운영은 별도 제품 단계

개인별 진도·교사 대시보드·구독·동기화가 필요해지는 시점에는 현재 정적 앱에 임시 저장소를 덧붙이지 않는다. 인증·데이터베이스·서버 측 권한 검증을 갖춘 별도 플랫폼 전환으로 다루고, 구조 스냅샷과 학습 이벤트의 보존 기간·삭제·동의 정책을 먼저 확정한다.

## 7. 검증과 출시 게이트

| 게이트 | 자동 검증 | 실제 기기 검증 | 통과 조건 |
|---|---|---|---|
| 레이아웃 | 320/375/390/430px 및 가로 방향 스크린샷 회귀 | iPhone Safari, Android Chrome, 태블릿 브라우저 | 핵심 조작이 가려지지 않고 가로 스크롤 없음 |
| 터치 | Pointer Event 단위 테스트, 슬롯·후보·Undo 계약 테스트 | 한 손 조립, 두 손가락 탐색, 긴 손가락 탭 | 원치 않는 원자 추가·카메라 이동이 재현되지 않음 |
| 접근성 | ARIA·포커스·감소된 모션·목표 면적 검사 | VoiceOver, TalkBack, 200% 확대 | 동일한 조립·삭제·Undo 결과에 도달 가능 |
| 성능 | Lighthouse·번들 크기·장기 프리셋 전환 측정 | 저가형 Android에서 10분 조립 세션 | 입력 지연·메모리 누수·과도한 발열이 관찰되지 않음 |
| 오프라인 | 서비스 워커 캐시·오프라인 새로고침 테스트 | 비행기 모드에서 구조 생성·복원 | 앱 셸·최근 구조·기본 레슨이 열리고 상태가 명시됨 |

출시 전 사용성 검증은 초심자 5~8명과 유기화학 학습자 5~8명을 대상으로 실시한다. 측정값은 첫 조립 성공까지의 시간, 슬롯 선택 실패율, 의도하지 않은 카메라 이동 비율, Undo 후 복구 시간, 한 레슨의 끝까지 도달한 비율, 그리고 학생이 자신이 만든 구조의 전하·기하를 설명하는 정확도다. 이 값이 개선되지 않으면 하단 시트나 제스처를 더 추가하기보다 현재 흐름을 단순화한다.

## 8. 의사결정 요약

가장 먼저 구현할 것은 PWA나 새 분석 기능이 아니라 **M1 모바일 셸**이다. 상단 정보 밀도와 사이드바를 해결하지 않으면, 슬롯 링·2D 드래그·오프라인 저장도 작은 화면에서 일관된 학습 경험이 되기 어렵다. 그다음 M2로 터치 조립을 안정화하고, M3로 교재 정렬형 레슨을 얹으며, 사용자가 실제로 모바일에서 반복 학습한다는 근거가 쌓인 뒤 M4 PWA를 도입한다.
